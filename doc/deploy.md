# Развертывание приложения

В настоящее время приложение работает на VPS и доступно по адресу https://comunicore.mooo.com/.

Развертывание происходит автоматически скриптами GitHub Actions. Есть тестовое развертывание и продакшин.

## Production окружение

Merge в ветку `main` автоматически развертывает приложение на сервере по адресу https://comunicore.mooo.com/ (для вливания в `main` нужно одобрение слияния).

Push в ветку `deploy` развертывает приложение на сервере по тому же адресу https://comunicore.mooo.com/ только без одобрения слияния.

## Testing окружение

|ветка|web|
|--------|-------|
|`deploy_test`|https://test-comunicore.mooo.com|
|`deploy_barbaris`|https://barbaris-comunicore.mooo.com|
|`deploy_narzan`|https://narzan-comunicore.mooo.com|

`push` в ветку создает тестовое окружение на 12 часов со своими копиями данных. Данные берутся из production окружения. Через 12 часов приложение бакенда завершается и данные удаляются (только тестового окружения, разумеется).

Изменение данных тестового окружения никак не влияет на production. У каждого окружения свои данные. Тестовых окружений аж 3 штуки (независимых). Чтобы понять, не используется ли конкретное тестовое окружение - нужно зайти на его веб адрес. Если там что-то есть, то после создания окружения не прошло 12-ти часов и, возможно, его кто-то использует (после завершения 12-ти часов работы данные тестового окружения удаляются насовсем, поэтому даже через nginx выдается пустота - там нет даже папки с файлами). Тогда нужно искать владельца в телеге или найти окружение, которое никто не использует.

## Алгоритм работы скриптов развертывания на VPS

Развертывание (как production, так и testing) происходит с помощью GitHub Actions. На GitHub в Secrets лежит приватный ключ для доступа по ssh к серверу, но по этому ключу доступен только запуска скрипта (никакого shell'а по нему получить нельзя).

Скрипт развретывания на VPS получает от GitHub архив со скомпилированными банарниками приложения, миграции базы данных и файлами фронтэнда. Скрипт после получения архива:

- останавливает сервис,
- распаковывает архив,
- для production делает бакап текущей версии,
- удаляет файлы бинарника и фронтэнда предыдущей версии,
- для tesing удаляет из базы все таблицы и функции и заливает текущую версию из production,
- копирует файлы фронтэнда и бинарников в нужные директории,
- запускает миграции базы данных,
- запускает сервис comunicore.

Далее GitHub Action проверяет, что по http отвечает версия сайта с соотвествующим хешом коммита. Если нет, то Action завершается с ошибкой.

## Файлы скриптов и конфигов в репозитории

Скрипты на VPS лежат в директории `/home/comunicore/bin`. А в репозитории они находятся в [`/config/deploy/vps/bin`](../config/deploy/vps/bin). В папке [`/backend/config/`](../backend/config/) лежат файлы systemd для запуска сервисов (production и шаблон для нескольких тестовых сервисов).
